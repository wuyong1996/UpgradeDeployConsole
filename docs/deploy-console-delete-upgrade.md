# 项目信息与删除功能升级

## 1. 安装新版

最新版包含“删除前备份”选项及旧版自动项目识别兼容。部署包统一用[打包命令](deploy-console-package.md)生成；新包成功后旧交付自动删除，历史版本名不再作为下载入口。

将当前`deployment-artifacts/`内的最新`.tar.gz`和`upgrade-deploy-console.sh`上传到服务器`/root/`，等项目当前操作完成并暂停自动发布计划，再执行同目录`DEPLOY.md`给出的准确命令。生成的升级脚本不传参数时也默认使用本次包名：

```bash
bash /root/upgrade-deploy-console.sh
```

不读取或要求.sha256。升级包存在则安装，不存在则明确提示跳过；面板健康后清理匹配的本次包及解压目录，安装/健康检查失败保留现场。这是完整升级包，保留密码、项目、端口、Git凭据、HTTPS和MySQL设置；安装不会删除项目。浏览器Ctrl+F5刷新后核对删除选项，按需恢复项目自动计划。

## 2. 新增展示信息

- 数据库：明确的数据库名称、连接地址、端口、项目账号、迁移状态及已应用迁移数；不显示密码或连接串。
- 服务页顶部：Git源码与构建缓存的本地目录。它是各次prepare/front/back拉取工作目录的父目录。
- 后端：systemd服务名称和开机启动状态。原有部署路径、提交、端口与HTTPS访问链接保留。

连接健康沿用既有实例TCP检测，不表示已执行数据库读写验收；迁移数来自面板保存的迁移记录。

## 3. 删除项目

### 旧项目提示“含人工接入配置”

20260923自动接入脚本没有写入项目级`autoManaged`，当时创建的前端也可能缺少该字段。后续自动补接前端/数据库不会补写项目级标记，因此“项目级未记录、front/back均为true、database.autoProvisioned=true”的项目也会被初版删除器误判。

升级本修正版即可重新识别，无需手工修改JSON、重新发布或重新建库。保持总关停状态，刷新页面后重新打开“删除项目”。修正版只兼容缺失字段，明确标为false的项目/服务仍拒绝；旧格式须验证原后端自动管理标记、专属构建账号、生成的systemd服务及其运行账号/目录，再执行完整的站点、路径、数据库和备份检查。预览不会重写接入文件。

如果仍无法核对归属，弹窗会列出前提与待核对文件位置。请管理员核对该项目的接入文件、实际服务身份和独占目录；人工接入、共享资源或缺少生成证据的项目不能通过本按钮强制清理。不要为通过检查直接把`autoManaged`改成true。当前自动识别不覆盖缺少全部管理标记的人工/纯前端旧接入。

### 操作步骤

1. 点击“总关停”，等待完成，确认没有正在执行的项目操作。
2. 点击出现的“删除项目”。服务器先核对实际进程、停止标记、目录与服务归属、数据库实例/账号及活动连接；冲突时显示原因，不提供强制绕过。
3. 弹窗列出确切的站点、服务文件、前后端部署链接/发布版本、Git源码/构建缓存、运行配置、运行数据、项目数据库及专用账号，默认勾选“删除前备份（推荐）”，并显示备份位置。
4. 保持默认备份，或取消勾选“删除前备份（推荐）”。选择不备份后，另需勾选“我确认不生成备份，删除后无法通过本次操作恢复数据”。
5. 输入项目标识并勾选“我确认删除此项目及其数据库数据”，点击“备份并删除项目”或“不备份删除项目”。请求进入发布记录，明确记录选择及清理进度。

删除范围由root保护的项目接入文件推导，网页不能指定额外路径。只支持本面板自动创建的前后端以及自动创建的MySQL项目库（也支持未配置数据库的自动项目）。人工接入服务、外部库、Docker/系统共享数据库或归属冲突会阻止删除，不能误当作独立项目清空。若数据库还有活动连接，关闭本项目连接后再重试。

MySQL管理账号需要直接拥有`PROCESS`权限，以确认所有项目连接已关闭；仅通过角色取得该权限的账号也会被保守拒绝。本功能不自动提升管理账号权限。现有项目专用账号保持锁定且没有活动连接后才允许删库。

清理完成后删除面板项目和它的已保存Git凭据，端口不再作为已登记服务保留；实际端口仍须经过占用探测才能再次分配。空的部署父目录、Linux隔离账号及其账号目录保留；项目current/releases、源码、运行数据/配置已清理。共享MySQL进程及数据目录、Nginx进程及其他站点、全局HTTPS证书、面板密码、其他项目不在删除范围内。

## 4. 备份与失败处理

**选择备份时**，恢复材料保存在`/var/lib/deploy-console-archives/<项目标识>/<删除指纹前缀>/`，目录700、文件600，仅root访问，包含运行密钥等敏感恢复信息，不能上传到Git或公开分享。预览、操作事件及最终结果显示实际目录。

- `files-*.tar.gz`：本次文件资源的压缩备份；归档内顶层数字编号对应`manifest.json`的`resources`数组顺序。
- `database-backups/database-*.sql.gz`：实际mysqldump备份（无数据库项目没有该项）；包含项目表、视图、存储程序等，具体由服务器权限与MySQL能力决定。
- `manifest.json`：路径对应关系、接入配置及压缩文件SHA256；面板会读完压缩数据并校验摘要后才开始删除，重试时再次校验。

已有恢复备份和审计不自动清理，因此删除项目不等于立即释放所有历史备份占用。选择备份时，备份失败或空间不足不会开始删除。文件系统备份不等于恢复演练；正式使用前应在测试服务器对一个可丢弃项目完成删除与恢复验收。

**选择不备份时**，跳过文件归档、mysqldump及备份目录创建，本次没有恢复备份。仍检查停止状态、资源归属、挂载/链接、数据库账号和连接；共享服务及独立保存的删除恢复备份不删除。项目主机状态目录中的`database-backups`属于项目清理范围，会随项目删除；独立的`/var/lib/deploy-console-archives/`删除恢复备份目录保留。只保留重试必需的删除阶段/归属元数据和审计，不在不备份删除记录中存放数据库密码。

若上次失败仍在`preparing`阶段（例如备份失败，尚未开始清理），可重新打开弹窗改选不备份；此前已经生成的部分备份文件保留，但不能视为完整可用的恢复备份。一旦备份通过或不备份选择已确认进入清理阶段，重试固定原选择，页面会锁定备份选项；旧版删除任务/记录未含新字段时默认备份。

进入删除流程后，项目不能再启动、发布或编辑。清理失败仍显示项目及“重试删除”，沿用原范围继续；已完成的删库步骤不会重复执行。数据库删除是DDL而非跨步骤事务：如果执行中断而结果不明确，会停在`dropping-database`，要求管理员核对库与账号实际存在情况、备份和记录，不能自动重放或直接清空删除标记。记录位于`/var/lib/deploy-console-deletions/<项目标识>.json`，仅root可读写。

恢复需管理员按以下顺序进行：

本节仅适用于已成功生成并校验恢复备份的删除。不备份删除只能依靠另行保存且验证过的历史备份，可能有数据损失，不能通过本次操作恢复。

1. 保持项目停止，核对记录中的原项目、MySQL实例UUID、库名、备份摘要及当前目录归属，不覆盖其他项目或后来创建的同名库。
2. 在独立恢复位置查看文件归档及`manifest.json`；不要将未知归档直接解压到`/`。数字目录必须按清单映射回原路径，current符号链接只能恢复到本项目releases内。
3. 在已确认的MySQL实例重建原项目库和专用账号，再向明确指定的空项目库导入SQL；凭据与运行配置从受保护文件备份恢复，不打印到终端或日志。需要先处理多语句删除中哪些步骤已成功的实际状态。
4. 恢复目标接入文件、运行配置、项目主机状态和systemd/Nginx项目配置，执行Nginx校验及daemon-reload。服务器删除完成但面板项目已移除时，由管理员重新录入原项目资料及Git凭据，不能恢复过期删除意图或重放旧任务。
5. 确认恢复方案及删除记录已妥善处理后，先恢复数据库访问，再检查后端与前端；验证业务数据、健康检查和HTTPS后才重新开启自动发布。

本版不提供一键恢复，也不自动改变结果不确定的删除阶段。恢复是管理员确认精确目标后的单独操作。

实现依据：[MySQL DROP USER](https://dev.mysql.com/doc/refman/8.4/en/drop-user.html)说明现有会话不会随账号删除立即终止，因此删除前检查项目活动连接；[Python安全目录清理](https://docs.python.org/3/library/shutil.html#shutil.rmtree)用于防止递归删除跟随符号链接。本机测试模拟Linux服务和MySQL命令，不替代服务器上的实际验收。
