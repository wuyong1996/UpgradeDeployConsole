# 生成最新部署包

在独立仓库根目录执行：

```powershell
pwsh -NoProfile -File scripts/Package-DeployConsole.ps1
```

默认以UTC日期时间（含毫秒）生成版本，也可指定`-Version 20260924-custom`。已有同名版本会拒绝覆盖，换新版本重新生成。

流程：恢复npm依赖 → 构建前端 → 按NuGet锁文件恢复 → 发布.NET Release → 装入Linux脚本/文档 → 校验每个归档文件及页面资源 → 交付新包 → 删除旧交付材料。打包使用独立临时目录，结束后清理临时目录。

成功后`deployment-artifacts/`只保留三项：

- `deploy-console-server-<版本>.tar.gz`
- `upgrade-deploy-console.sh`（默认指向本次版本）
- `DEPLOY.md`（本次版本的准确安装命令）

按用户要求，不保留旧压缩包、旧解压/发布目录、校验文件、旧升级脚本或历史接入附件。构建或归档核验失败时不会清理旧交付。清理失败会报告错误，不冒充全部完成；修复占用/权限后用新版本重新打包。生成目录不是存放手工文件的地方；发现不认识的文件、软链接或目录联接时会停止，避免越界清理。并发打包通过文件锁阻止。

上传最新压缩包和升级脚本至服务器`/root/`，按`DEPLOY.md`执行。升级脚本不读取.sha256；服务器端仍按健康检查及内容匹配规则清理本次包/解压目录。这个本地清理流程不触及服务器已安装版本、项目数据、数据库或恢复备份。

源码、运行配置保留；`.local/`和`deployment-artifacts/`均不提交Git。历史验证记录中的旧包名称只作历史证据，不能再按旧链接下载。
