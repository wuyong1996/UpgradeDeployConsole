# 总开始功能升级说明

> 下列历史版本的包已按用户要求不再保留。当前请按[最新打包与部署说明](deploy-console-package.md)获取完整包，并使用生成的DEPLOY.md安装；以下功能与排查说明继续适用。

本次修复“总关停后，发布项目被拦截，无法一次恢复”的问题。全停时总按钮显示“总开始”，点击后依次恢复数据库、后端、前端。待初始化数据库会通过后端发布完成初始化；恢复成功后前后端自动发布计划保持暂停，需要时手动打开。

## 上传与安装

用 WinSCP 将新包 `deploy-console-server-20260924-start-all.tar.gz` 上传至 `/root/`。不要重复安装旧的 `mysql` 包。在服务器 root 终端执行：

先将新版`upgrade-deploy-console.sh`上传至`/root/`，覆盖旧脚本；无需上传校验文件。

```bash
bash /root/upgrade-deploy-console.sh /root/deploy-console-server-20260924-start-all.tar.gz
```

新版脚本不读取或要求`.sha256`。升级包存在则安装，不存在则提示跳过安装；两种情况均在面板健康检查通过后，清理能够确认与当前安装内容一致的同版解压目录，以及本次包和可选的旧校验文件。不存在的文件直接跳过。支持本次临时目录、旧版随机解压目录及直接解压的同名上传目录；解压外层含其他文件、存在软链接、挂载点、其他版本或内容不符的目录会保留并说明原因。安装/健康检查失败时保留现场。旧压缩包内说明不更新，请使用这里的新脚本；不会把“缺包跳过”报告为“已升级”。

安装器同时更新页面、API 和服务适配器；保留密码、Git 凭据、项目状态、MySQL 管理连接与现有业务数据。请等当前发布任务完成后再升级。成功后清理本次上传文件，失败则保留用于核对；宝塔的面板反向代理无需修改。本次不需要再次推送业务仓库代码。

## 页面操作与核对

1. 浏览器按 `Ctrl + F5` 强制刷新，进入已总关停的项目，应看到“总开始”。
2. 点击“总开始”，在发布记录查看数据库恢复、后端初始化/启动、前端启动的进度。
3. 成功后按钮恢复为“总关停”，服务卡片显示实际运行状态；需要自动更新时分别打开前后端“自动发布”。
4. 如失败，查看最新“总开始”记录；已经恢复的服务可能继续运行，可再次总关停。不要删除数据库或清除迁移标记来跳过错误。

安装后以下两处应显示相同的新页面脚本名 `/assets/index-IZvUOBMn.js`：

```bash
grep -oE '/assets/index-[^" ]+\.js' /opt/deploy-console/current/wwwroot/index.html
curl -fsS http://127.0.0.1:5088/ | grep -oE '/assets/index-[^" ]+\.js'
grep -n 'def start_all' /usr/local/lib/deploy-console/host.py
```

本机已做回归验证，实际服务器的 MySQL 初始化和 Linux 服务恢复需在升级后核对发布记录。本次不会替用户执行生产迁移或远程升级。
